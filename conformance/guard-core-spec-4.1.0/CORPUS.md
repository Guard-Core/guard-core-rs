# Fixture Corpus (spec 4.1.0)

Vendored byte-identical copy of the reference repo's
`guard-core/specs/fixtures/cases/` at spec 4.1.0, plus the fixture authorship
rules (`FIXTURES_README.md`, copied from `specs/fixtures/README.md`).

Provenance: generated by `specs/fixtures/tools/generate_fixtures.py` in the
guard-core reference repo; expected values come from running the live
reference engine, never hand-written.

## Suite kinds

- `kind: "detect"` (12 suites, 184 cases): request-content detection
  verdicts. Consumed by this repo's runner (go/php/ts consume them too).
- `kind: "pipeline"` (5 suites, 35 cases): pipeline-level 4.1.0 behavior
  (exempt_ips, CORS, geo country rules, security headers, rate-limit tiers,
  route detection exclusions, passive_mode, the 400 detection shape,
  custom_error_responses, on_block payloads, behavior rules) recorded through
  the reference's real check pipeline. The rust engine has no pipeline port
  yet, so the rust runner loads only the detect suites (see the `consumers`
  list per suite in `index.json`); the go/php/ts runners consume the
  pipeline suites through their own engines.

## Detect drift vs spec 4.0.3

None: all 184 detect cases regenerate byte-identical against the 4.0.3
vendored expectations. The 4.1.0 parity work changed pipeline behavior, not
detect verdicts.
